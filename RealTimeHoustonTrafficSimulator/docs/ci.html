Shipping

Continuous integration & updates

This software is updated often. Every push and pull request runs automated checks so the marketing site, simulator, and packages stay shippable — created by Ejay Gabriel.

What CI does

  • Installs dependencies with npm ci
  • Verifies required pages and PWA assets exist
  • Runs a full Vite production build
  • Uploads the dist/ artifact for inspection
  • On main / master pushes, packages the Windows zip artifact

Workflow file

.github/workflows/ci.yml

Triggers on push and pull request to main/master, plus manual workflow_dispatch.

Local parity

npm ci
npm run build
npm run package:win   # optional desktop zip

Release rhythm

  • Simulator build tags (#vtag / console string) bump when behavior changes
  • Web app users get updates on refresh / reinstall of the hosted build
  • Desktop zip users re-download when a new package is published
  • City modules (LA, NYC, Austin, …) will land through the same CI path

Secrets in CI

Production builds do not need live API keys. If you add deploy steps later, store FLIGHTAWARE_API_KEY / TOMTOM_API_KEY only in GitHub Actions secrets — never in the client bundle.
